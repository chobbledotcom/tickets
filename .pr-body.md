## Behavior

The add, duplicate and edit listing forms now use the vocabulary of the chosen listing template.

- **Template words:** a template maps to a ticket, item, hire, donation or subscription vocabulary. The words cover the unit, its plural, the buyer, capacity, the public page, the document, and the pricing heading.
- **Create and duplicate:** the page takes the template id from the picker and passes it to the form state. A physical product form says "Item price" and "Max items per purchase". A one-off event form says "Ticket price" and "Max tickets per purchase".
- **Edit:** the page infers the stored listing's template, so a saved physical product keeps item words in its form.
- **Custom and unknown templates:** both use the neutral item vocabulary.
- **Refusals:** form validation and server refusals use the same words. A missing unit price says "Enter a price for the item" on an item form and "Enter a price for the ticket" on a ticket form.

## Current-system value and caller

Caller: `listingFormState` in `src/ui/templates/admin/listings/form-sections.tsx` builds every listing form. `adminListingNewPage`, `adminDuplicateListingPage`, and `ListingEditPanel` pass the template object, and `handleCreateListing` and `saveListingEdit` pass it on the write paths.

Before this branch the form always used ticket words. It received only an `isTemplated` boolean, so it had no template id for the vocabulary. The edit page also had no template for its saved listing.

## Facts and data

- Trusted: the template id chosen on the create form, or inferred from the stored listing on edit.
- Trusted: the locale messages for each vocabulary in `src/locales/en/listings-table.json`.
- Observed: the rendered form and the refusal text are the only outputs. This change adds no database reads, database writes, or provider calls.

## Old path deleted

- The fixed `listings_table.tickets_pricing` heading. Each form now receives its template's `pricingHeading`.
- The `isTemplated` boolean argument of the old `listingFormPageState`. The new `listingFormState` takes the template object so the copy has its id.
- The ticket-specific field labels and hints in `src/ui/templates/fields/listing.ts`. The fields read their words from `listingCopy`.
- The ticket-specific unit price and maximum price refusal text.
