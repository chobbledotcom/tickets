The useful mental model

A provider charge is now the unit of refund truth.

The large diff replaces route-local guesses with one durable, revisioned charge record. Attendee rows coordinate work; the charge record decides whether money may move.

01 · one authority

payment_charges owns provider truth

Provider identity, exact Money, send generation, evidence, local recording and recovery state live together.

02 · persist first

The send is armed before network I/O

A crash can leave uncertainty, but never an invisible permission to send the same keyless refund again.

03 · two facts

Cash returned ≠ ledger recorded

Provider completion and local accounting retire separately, so a failed ledger write cannot erase returned money.

Silent booking errors Recover only from matching stored facts; otherwise rethrow.
Population decryption Refund All decrypts 0 on GET and at most 1 on POST.
DB-key privacy New PII and raw references require the owner key.

03 · cost and disclosure are explicit

Bound first. Decrypt second.

Large-set questions use indexes and state mirrors. Sensitive detail is opened only after the request has selected one bounded target.

0attendee decryptions on Refund All GET
≤1attendee decrypted per Refund All POST
10references allowed per attendee
100shared holders; row 101 refuses first
5concurrent provider calls
20IDs per keyset-paged recovery list
owner-key secret

Raw personal/payment identity

Modern attendee PII and new raw provider references use owner public-key ciphertext. DB + DB_ENCRYPTION_KEY is not enough to open them.

blind identity

Searchable, not reversible

DB-keyed HMACs join references, callbacks and confirmations without exposing the raw provider value.

DB-key envelope

Finite local coordination

Claim, outcome, review and unrecorded markers are encrypted local state. They must contain no buyer PII or provider bodies.

intentional plaintext

Queryable operations

Provider, Money, lifecycle mirrors, due dates and narrow protected words remain visible so SQL can find work safely.

Caveat: provider credentials are DB-key encrypted and can be used by someone holding the database and environment key. Dormant v1 owner keys retain the older boundary until their existing upgrade ceremony runs.

Visitors

Owners send/decide; managers observe; callbacks and rendered recovery controls use real routes.

Storage and races

Migrations, constraints, CAS, claims, crashes, settlement, merge/delete/prune and bounds are exercised directly.

Architecture

Static checks reject a second authority, direct adapter calls, ambient refund selection and dead recovery controls.

Decision quality

Exhaustive state tables and mutation suites attack branches where a wrong money answer could otherwise hide.

Full Cucumber catalogue: 262 scenarios / 1,877 steps. These prove code invariants and simulated provider/race behaviour—not provider uptime, unusual production history or the future aggregate migrations. The whole-branch mutation wrapper refuses this >100-file stack; the safety-critical modules were run directly with zero survivors.

05 · honest edges

What this PR deliberately does not pretend.

Old unqualified payments

They get reduced refund functionality. There is no compatibility reader or provider guess.

Refund All

One attendee per submission—not yet a durable, resumable listing-wide intention.

Booking obligations

Stable order identity, shared-charge allocation and free package-member cancellation remain later work.

Checkout cutover

A confined pre-cutover session selector cannot refund; its replacement must delete it atomically.
