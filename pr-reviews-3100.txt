P1
==

1. The whole scanner page dies when the offline side cannot wire.
   src/ui/client/scanner.ts:210, src/ui/client/scanner-offline.ts:123,128,160
   initOfflineScanner is unguarded and throws synchronously for
   navigator.serviceWorker undefined (secure-context only), a blocked store
   (SecurityError), a queue stored in another shape, or no
   Uint8Array.fromBase64. Base caught this, guarded "serviceWorker" in
   navigator, and read a blocked store as off; its regression test was
   deleted. No camera and no manual check-in at a door that never opted in.
   Rules R6, R19, R24.
   Fix: restore the judged degrade to online-only or feature-detect each
   dependency; restore the deleted test.

2. A quota failure on a page-load refresh deletes the still-valid list.
   src/ui/client/scanner-offline-switch.ts:59-61
   setItem is atomic, so a QuotaExceededError during the refresh leaves the
   old list intact; sayDownloadFailure then deletes it while the mode key
   stays "1". The door is left with the switch on, no list, and every scan
   refused with "turn on offline mode", which is already on.
   Rules R10, R24.
   Fix: remove the list only when arming; never on a refresh; keep mode and
   list consistent.

3. The duplicate-queue guard sits outside the write.
   src/ui/client/scanner-offline-ui.ts:131-156
   The guard runs before the showQuantitySelect await; a camera scan during
   an open manual quantity prompt passes the empty-queue check, and each
   caller then queueCheckIn with distinct operation ids, so the same ticket
   is checked in twice.
   Rule R17.
   Fix: re-check inside a synchronous read-test-write helper, after the ask.

4. Guest names persist in browser storage past sign-out.
   src/ui/client/scanner-offline.ts:53, src/shared/ticket-cache.ts
   The cache entry now carries plaintext guest names/details in
   localStorage, retained indefinitely past sign-out, role revocation, and
   the 12-hour TTL (which gates use, not retention). Base stored only
   digests. Sign-out never touches scanner storage.
   Rules R15, C30.
   Fix: clear scanner-tickets-* and the mode keys on sign-out, or bind the
   list to the user id and drop it on mismatch.

5. The branch mutation gate fails at the pushed head.
   scripts/mutation/equivalent-mutants/*.txt, scripts/mutation/runs.jsonl
   36 entries on 13 files no longer match the text they suppress; three
   records were deleted although their mutants still generate
   (expireRow/settleRow className, doorKeyBytes error text); the recorded
   runs cite pre-final commits (ad4f4d837, where scan-flow.ts differs by 33
   lines). The gate was never run on the pushed head, and CI does not run
   it.
   Rules R41, C16-C18, C53.
   Fix: run the gate on the final head, re-stamp or delete each reported
   entry, and kill or record the three surviving mutants.

P2
==

6. scan-search is missing from the JSON path pattern.
   src/features/content-type-rules.ts:16
   An expired session answers 303 to the login page instead of the 401 JSON
   every sibling scan route answers; the client follows the redirect, passes
   res.ok, and dies in v.parse with a generic page error.
   Rules R4, R36, C1.
   Fix: widen SCAN_API_PATTERN to scan(?:-cache|-search)? and add the
   unauthenticated 401 test the cache route has.

7. Every search decrypts the whole door.
   src/features/admin/scan-search.ts:45
   scopeAttendees reads ATTENDEE_FIELDS (six money subqueries per row) and
   decrypts every line's PII to return 20 names; the sibling cache path
   bounds exactly this work at 250 people. Base paid it once per page
   render.
   Rules R33, C4.
   Fix: read only the roster's fields (the BROWSING_FIELDS precedent) and
   consider a short-lived decrypted-roster cache.

8. The paged download is not a snapshot.
   src/shared/db/listings/attendees.ts:171
   Pages select attendee id > cursor over the live join, so an attendee
   below the cursor who gains a line mid-download is never returned; their
   digest is absent and offline scans refuse a valid ticket.
   Rules R17, R25.
   Fix: capture a membership high-water mark on the first page inside the
   signed cursor and bound every page's line ids by it.

9. One shared quantity field carries two facts.
   src/shared/roster-option.ts:15
   The roster fills total owed at the door (scan-door.ts:152) while the
   cache fills what one scan admits (scan-cache.ts:84-88); the same person
   shows "3 tickets" online and "2 tickets" offline at a one-listing-per-
   scan group.
   Rules R1, R3, R8.
   Fix: carry the two facts under separate names.

10. The name-search rule is declared three times and diverges.
    src/ui/client/scanner-offline-ui.ts:198, src/features/admin/scan-search.ts:21,24,
    src/ui/client/admin/manual-search.ts:43
    The server sorts by name then caps 20; offline slices the first 20 in
    digest order with no sort, so the same query returns different people
    depending on connection, in the mode with no network to fall back on.
    Rules R1, R2, R35.
    Fix: one shared matcher and limits module used by the route, the client
    pre-check, and the offline search.

11. A temporary HTML 503 aborts the whole queue replay.
    src/ui/client/scanner-offline-sync.ts:151-157
    The documented databaseBusyResponse is an HTML 503 page; res.json()
    throws and answerOrNull rethrows everything but NetworkError, so one
    transient 503 skips every remaining row. Base caught per item and
    continued.
    Rules R11, R24.
    Fix: treat a non-ok answer as not-sent-yet and keep walking the rows.

12. The manual pick asks a question its route always refuses.
    src/ui/client/scan-flow.ts:234 vs src/features/admin/scan-answer.ts:254

    server converts wrong_listing into 404 not_found, and the merged test
    models the unreachable state.
    Rule R3.
    Fix: pass the ask list per caller; the manual pick asks
    select_quantity and verify_id only.

13. Every refused search reads as a connection fault.
    src/ui/client/admin/manual-search.ts:57

    Rules R11, R40.
    Fix: branch on status; refusals get the reload word, and the copy stops

14. An unknown scan answer status silently degrades.
    src/ui/client/scan-answer.ts:51

    Rules R1, R4.
